# 0.2.16 — 档位菜单挂到星号上

## 为什么

0.2.15 的"先选档"放在了错误的位置：composer 里塞了个原生 `<select>`。深色输入框里它显示成一个孤零零的"标准"，点开还是系统自带的浅色菜单 —— 看起来像坏掉的残留 UI，而不是这个功能的一部分。

## 发生了什么

- **档位菜单现在挂在星号上**：点星号弹菜单（七档、当前档打勾），点一行就按那一档增强。选和确认是同一次点击，但**点之前不花 token**。
- 菜单是 `role="menu"` 的 portal，跟随星号的盒子定位（上方优先，边缘自动夹紧）；用宿主主题令牌，和结果面板一个观感，不再是系统浅色弹窗。
- 行是 `role="menuitemradio"` + `aria-checked`；↑↓ 移动、Esc 关闭、点外面关闭；**点星号本身不算"外面"**，它自己负责开合，避免双处理。打开时焦点落在当前档那一行。
- `start(mode)` 收下了刚刚确认的档位，所以同一 tick 里选的档就是真正发出去的档（只改状态会晚一帧 —— 那是上一版潜在的坑）。
- 星号的 tooltip 带当前档位；调用进行中按钮不响应。
- 原生 `<select>` 与 `src/client/ModePicker.tsx` 一并删除，样式和文案换成菜单的一套。

## 验证

- `tsc -p .` 干净；`vitest run`：38 文件 / 535 用例全过。
- `lib/index.js` 与 `lib/client.js` 已重建，`tests/preflight-built.mjs` 通过。

## 生效方式

宿主加载 `lib/`，**重启 DSH** 之后生效。
