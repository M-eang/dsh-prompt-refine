# 0.2.14 — 面板里直接换档

## 为什么

0.2.13 把档位从 3 种扩到 7 种，但换档的入口在别处：设置页的枚举、或者记得住 `/enhance --mode`。正在看结果的时候想换一档，只能离开面板重来一遍；而"我正在判断的这份结果，是哪一档写出来的"在面板上根本看不出来。

## 发生了什么

- 面板标题栏下方多了一条档位条：七枚 chip，当前档高亮（`aria-pressed`），点一枚就用**面板自己那段原文**按新档重跑。
- 重跑和普通触发共用一个请求路径 `submit(text, mode, plainRefs)`——流式、取消、结算、错误映射只有一份。
- 请求体显式带上 `mode`：面板高亮的就是宿主实际跑的档位。
- 重试（Retry）同样改成用面板原文，且只对"真的发出去过"的错误显示；本地守卫拒绝（空/超长/相位忙）既没有重试也没有档位条。
- 客户端设置镜像增加 `mode`（第五个字段），解码走 `isEnhanceMode`，默认值与 `DEFAULT_CONFIG.mode` 由测试锁死。

## 验证

- `tsc -p .` 干净；`vitest run`：37 文件 / 525 用例全过（新增 6 个）。
- `lib/index.js` 与 `lib/client.js` 已重建，`tests/preflight-built.mjs` 通过。

## 生效方式

宿主加载 `lib/`，所以**重启 DSH** 之后新面板才会出现。
