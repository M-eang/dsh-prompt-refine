## 0.2.18 (本地线 · 2026-11-12 — a token no longer repaints the panel)

**One store, one version number, so every token woke everything.** The panel, the composer trigger, the undo bar and the history list all subscribe to the same store, and a streamed delta counted as a store mutation. On a fast model that meant 50–100 notifications a second, each re-rendering the panel's header, seven mode chips, up to ten history rows and the footer — chrome that a delta never changes — before the one `<pre>` that did. The visible symptom is a panel that gets sticky the longer the rewrite runs.

- **The streamed text is its own slice** (`src/client/ui-state.ts`): `subscribeStreaming(listener)` + `getStreamingText()`. `flushPendingDelta` now wakes only those listeners and deliberately does **not** bump `version`, so a delta is no longer a coarse state transition. Everything that actually is one (open, settle, error, close, undo, history, picked mode) still notifies everyone.
- **The live body owns the subscription** (`src/client/ResultPanel.tsx:245-277`): a new `StreamingBody` renders the spinner copy before the first token and the text after, reading the slice through `useSyncExternalStore`. The panel around it keeps subscribing to coarse state only, and no longer reads `state.streaming` at all.
- **The snapshot is a primitive** (`getStreamingText` returns `string`), so `useSyncExternalStore` compares by value instead of by object identity — no snapshot caching needed and no risk of the "getSnapshot should be cached" warning.
- **Same batching, narrower fan-out**: the per-JS-turn coalescing from 0.2.9 is unchanged, so a burst of tokens still collapses into one mutation and one notification.
- Tests: the batching regression now asserts against the streaming slice, and a new case (`keeps coarse subscribers asleep while deltas stream`) pins the contract — one fine-grained notification per flush, zero coarse ones, blank slice once the call settles. `tsc -p .` clean; 541 tests across 38 files.
- Not fixed here (no evidence it is the cost): the panel still renders the whole streamed string, so a 30 KB rewrite still lays out 30 KB of text per frame. If that turns out to matter, the next step is a tail window during streaming, not more store surgery.

## 0.2.17 (本地线 · 2026-11-12 — the menu now behaves like a menu)

**0.2.16 made the picker visible; a review of it found the seams.** The menu was reachable and themed, but it was still a widget that looked like a menu rather than one that behaved like a menu: it answered arrow keys it did not own, gave no Tab story, never said which mode it would run, guessed at focus, and mis-declared its own contents to assistive tech. Six fixes, no behaviour change to picking or spending.

- **Arrow keys belong to whoever has focus** (`src/client/ModeMenu.tsx:121-131`). The document-level handler now returns unless the active element is inside the menu, so ↑/↓ pressed on the composer after Tab moves the caret or scrolls instead of being swallowed by a closed menu. Tab gets its own branch (`:115-120`): it closes the menu, hands focus back to the star, then lets the default move carry on — Tab lands on the next control instead of nowhere.
- **The star announces the mode it will run** (`src/client/EnhanceButton.tsx:240,266`). The label was a static `button.title`; it is now `button.titleWithMode` fed by the shared `settings.mode.*` keys, so the same string names the mode on the settings page, the panel strip and the trigger.
- **Focus returns on keyboard dismissal only** (`ModeMenu.tsx:52,108,144`). A `keyboardClosed` ref set by the Escape branch decides it, replacing the old guess that "focus ended up on `body`" meant the keyboard dismissed the menu — which also fired on pointer dismissals and put a focus ring on a star nobody clicked.
- **`role="menu"` holds only menu children** (`ModeMenu.tsx:155,174`). The title and hint rows are `role="presentation"`, so the menu's accessibility tree is seven `menuitemradio` rows rather than two invalid children plus rows.
- **`closeMenu` is a stable callback** (`EnhanceButton.tsx:248,251,290`). The inline arrow made the document listeners' dependency (`[anchor, onClose]`) change on every host render, re-registering two capture-phase listeners each time; `useCallback` keeps them registered once per open.
- **Placement follows the box, not just the window** (`ModeMenu.tsx:71-80`). The composer seat is `position: sticky`, not `fixed` (`@deepseek-ai/dsh-client-ui-conversation/src/client/skeleton/ConversationRoot.module.css:445`), so its rect still changes when the queue dock appears, the draft grows, or the transcript scrolls under it. The effect now also listens to `scroll` (capture, so inner scrollers count) and observes the anchor with `ResizeObserver` (skipped where the constructor does not exist). `place()` keeps the previous state object when the computed position did not move, so scrolling does not re-render the menu per frame.
- **The menu's chrome matches the panel.** 11px type instead of 12px, and `var(--dsw-shadow-lv2, …)` instead of a hard-coded `rgba(0, 0, 0, 0.45)`, which read as a black halo on the light theme.
- Tests: +5 — `tests/client-components.test.tsx` (the trigger announces the configured mode before any pick; focus returns after Escape but not after a pointer dismissal; Tab closes the menu and leaves the caret at the star; arrow keys are inert once focus has left the menu) and `tests/mode-menu.test.tsx` (Tab hands focus back to the trigger). `tsc -p .` clean; 540 tests across 38 files.

## 0.2.16 (本地线 · 2026-11-12 — the mode menu hangs off the star)

**A native select inside a dark composer looks like a bug.** 0.2.15 had the right idea (choose before you pay) in the wrong control: the platform draws the pill as a stray word next to the star and opens a light system menu over a dark row, so the picker read as broken chrome rather than as this feature. The selector now lives in the star's own menu, themed like the result panel, and one click on a row is both the choice and the go-ahead.

- **`src/client/ModeMenu.tsx`** — a `role="menu"` portal into `document.body`, positioned off the trigger's box (above when the composer sits near the bottom, otherwise below; right edges aligned, clamped to the viewport). It is portalled on purpose: the composer is a host-owned row that may clip absolutely positioned children, and the menu has to escape it to be clickable at all.
- **Rows are `role="menuitemradio"` with `aria-checked`**, labelled through the same `settings.mode.*` keys as the settings page and the result panel, the current one carrying a check. Arrow keys move between rows, Escape closes, a press outside closes, and a press on the trigger is deliberately excluded so the trigger keeps owning its own toggle (no double-handling). Focus lands on the chosen row so the menu is usable from the keyboard immediately, and returns to the star when it was dismissed from the keyboard.
- **One click = selection + confirmation.** `confirmMode` records the pick (`ui.pickMode`) and calls `start(mode)`; `start` now takes the confirmed mode so a pick made in the same tick is the mode that actually goes out (the state update alone would have been one render late — the 0.2.15 bug class).
- **The trigger no longer runs on click; it opens the menu.** `aria-haspopup="menu"` / `aria-expanded` say so, the tooltip carries the current mode (`button.titleWithMode`), and the button stays inert while any call is loading.
- **The native select is gone** (`ModePicker.tsx` deleted, its styles and the two `button.mode.title` lines replaced by menu copy: `menu.title`, `menu.hint`, `button.titleWithMode`).
- Tests: +5 net across `tests/mode-menu.test.tsx` (row order and labels, single check, click callback, Escape/outside/in-trigger press, plus the picked-mode store's notify-and-teardown semantics moved here) and `tests/client-components.test.tsx` (the star opens the menu, the picked row is what goes out, the menu closes after picking; every other test now drives the two-step gesture through one `clickEnhance()` helper). `tsc -p .` clean; 535 tests across 38 files.

## 0.2.15 (本地线 · 2026-11-12 — pick the mode before you pay for it)

**The strip was in the wrong place in the sentence.** 0.2.14 put the seven modes inside the result panel, where a click means *re-run* — so the first time you tried a mode you had already paid for a rewrite you did not want, and "which mode is this?" turned into a model call. Choosing and spending are now two different clicks: the composer grows a mode picker that costs nothing, and the panel's chips only select.

- **A mode picker in the composer** (`src/client/ModePicker.tsx`, next to the star). A native `<select>` pill labelled through the same `settings.mode.*` keys as the settings page and the panel strip, so the three surfaces cannot disagree about what a mode is called. Native rather than a popover because the composer is a cramped host-owned row that may clip absolutely positioned children, and a real select brings keyboard handling, type-ahead and the platform menu for free.
- **Selection is a store, not a request** (`src/client/ui-state.ts`: `getPickedMode` / `pickMode`). The choice is per session, in memory, and cleared when the composer unmounts (`registerSession`'s teardown). `undefined` means "use the configured `mode`", so the settings page keeps its meaning as the default rather than being a second, competing source of truth.
- **`effectiveMode = picked ?? settings.mode`** is what `start` sends; the shortcut path reads the same value, so a pick made with the mouse survives an `ctrl+alt+e` press.
- **The panel chips now only select** (`onPickMode`), and re-running is its own button (`onRerun`, `panel.rerun` = "用这一档重跑" / "Re-run with this mode") that appears only when the selection actually differs from the mode the panel ran. Reading seven labels costs nothing; only that button spends tokens. The strip itself stays readable (and now reachable) after a local guard rejection, where the old code hid it entirely because there was no call to repeat.
- **The highlighted chip means "the next run"**, not "the run you are looking at" (`ResultPanel` now prefers the `mode` prop over the request's own `state.mode`), which is the only reading consistent with a picker that exists before any result does.
- Tests: +9 across `tests/mode-picker.test.tsx` (option order and labels, unknown value ignored, store semantics, teardown clearing), `tests/result-panel-modes.test.tsx` (selection vs. the explicit re-run button, prop-over-request highlight) and `tests/client-components.test.tsx` (chip click spends nothing, a pick reaches the next request, re-run uses the panel original). `tsc -p .` clean; 534 tests across 38 files.

## 0.2.14 (本地线 · 2026-11-12 — the mode strip lives in the panel)

**Seven modes were only useful if you could compare them.** Choosing a mode meant leaving the result you were judging: open the settings page, change the enum, come back, run the draft again — or remember that `/enhance --mode` exists. The panel that shows the rewrite now also shows the axis it was written on, and switching costs one click.

- **A mode strip under the panel header** (`src/client/ResultPanel.tsx`, `.dsh-pe-modes` / `.dsh-pe-mode` in `src/client/styles.ts`). One chip per mode in the shared `ENHANCE_MODES` order, labelled through the existing `settings.mode.*` keys, the active one carrying `aria-pressed` and a filled state. The group is `role="group"` with the `settings.field.mode.label` name, so a screen reader announces "增强档位, 标准, 2 of 7" instead of seven loose buttons.
- **A click re-runs the panel's own draft, never the composer's** (`EnhanceButton.tsx` → `rerun`). Judging a result and typing something else at the same time used to be two different texts; a rerun now rewrites exactly the text whose result is on screen, so the two columns always describe one request. The guard chain is skipped on purpose — that draft already passed it — and re-checked defensively so a panel that never had a call behind it cannot send anything.
- **`submit(text, mode, plainRefs)` is the one request path**; the trigger and the strip share it, so streaming, abort, settle and failure mapping cannot drift between a fresh enhancement and a rerun.
- **Retry got the same treatment.** It now re-runs the panel's original draft instead of whatever the composer holds, and it only appears for errors that came back from a real call: a local guard rejection (empty / too long / busy phase) carries `localized` and no mode, so it renders with neither a retry button nor a strip.
- **The client mirror grew a fifth field** (`src/client/settings.ts`): `mode`, decoded through `isEnhanceMode` and pinned to `DEFAULT_CONFIG.mode` by `tests/client-settings.test.ts`. It is what the strip highlights before the first result arrives.
- **Every request now carries its mode explicitly** (`{ sessionId, text, mode }`), so the panel's highlight is what the host actually ran rather than what the settings page happened to say at render time.
- Tests: +6 — `tests/result-panel-modes.test.tsx` (order and labels, active chip, click payload, inert while loading, absent without a handler) and `tests/client-components.test.tsx` (rerun uses the panel original while the composer has moved on; a guard rejection offers neither retry nor the strip). `tsc -p .` clean; 525 tests across 37 files.

## 0.2.13 (本地线 · 2026-11-12 — seven output shapes, not three)

**The mode axis was measuring length when the complaint was shape.** `standard` / `concise` / `spec` all answer "how much output", so the two drafts that actually kept coming back — a rambling requirement that had to become something a person could build from, and a dictated voice-note that had to become readable prose — had no mode to land in. The list is now seven, each one a deliverable shape with its own discipline and its own budget:

| id | 标签 | budget | what the rewrite has to be |
|---|---|---|---|
| `standard` | 标准 | 0 (no cap) | unchanged: no addon, byte-identical request, historical behavior |
| `concise` | 精简 | 2000 | clarifies, never pads |
| `spec` | 规格 | 8000 | sectioned, testable deliverable specification |
| `engineering` | 工程提示词 | 8000 | a work order: objective, context, constraints, interfaces, ordered steps, acceptance |
| `colloquial` | 口语优化 | 2000 | dictated or term-stacked text turned into plain natural prose — no headings, no bullets, meaning unchanged |
| `research` | 调研论证 | 6000 | what is known, what is assumed, the alternatives, the criteria, the decision |
| `creative` | 创意发散 | 4000 | intent, audience, tone, hard constraints, several openings |

- **Every addon names itself.** Each non-default `systemAddon` opens with `Mode: <id>. ` — seven disciplines that do not announce which one is in force are seven disciplines the model blends. A test asserts the self-naming, so a new mode cannot be added without it.
- **`standard` stays the identity mode.** Empty addon, zero budget, byte-identical system prompt; a per-call `standard` also leaves the response shape untouched (no `mode` label), so older hosts see exactly the old payload.
- **Per-call override: `/enhance --mode <id> <text>`** (alias `-m`). The switch is explicit on purpose: `standard`, `spec` and `creative` are all plausible first words of a Chinese or English draft, and eating the first word of a draft is worse than typing one more flag. `/enhance modes` (or `档位`) lists the ids without calling the model. An unknown id fails at the command plane with `未知档位：<x>。可用档位：…` — never a silent fall-back to the configured mode.
- **The route accepts `mode` in the body** (`src/shared/protocol.ts`, `EnhanceRequestBody.mode`). Unknown or malformed values are ignored rather than rejected: a typo should cost the caller the override, not the whole rewrite. The HTTP path is deliberately more forgiving than the command path, and `tests/http-route.test.ts` pins both behaviours.
- **Resolution order is one line** (`src/orchestrate.ts`): `isEnhanceMode(options.mode) ? options.mode : config.mode` — the per-call value wins, the configured value is the floor. Append order is unchanged and still contractual: stance → strategy → mode addon → template addon → reference rules.
- **Settings surface.** `settings.field.mode.hint` (zh/en) and the schemastery description now enumerate all seven with budgets; the enum options are localized through new `settings.mode.*` keys instead of showing raw ids (`src/client/SettingsCard.tsx` now localizes `template` and `mode` enums, and only those).
- Tests: +8 across `tests/modes.test.ts` (order, self-naming), `tests/enhance-command.test.ts` (`modes` listing, `--mode`, `-m` + template, unknown id), `tests/orchestrate.test.ts` (per-call override, unknown fall-back) and `tests/http-route.test.ts` (body override reaches the system prompt). `tsc -p .` clean; 518 tests across 36 files.

**The operator contract is a source default, not a home-directory file.** Until now `armorEnabled: true` injected whatever `~/.dsh/prompt-inject.md` happened to hold, which made the shipped behaviour depend on a file the package does not own: a fresh install injected nothing, and the text actually in force could only be read by opening a dotfile. The armour body now lives beside every other built-in prompt.

A configured-but-unreadable file still reports its `note` instead of falling back silently, and the built-in body is what an empty `armorFile` + empty `armorText` resolves to.

With no file configured the built-in body is what `armorEnabled: true` injects, so the armour is on by content rather than by a path an operator has to know about; pointing `armorFile` at a file restores file-driven text. `armorEnabled` stays `false` by default — the switch is unchanged, only the body's home moved.

## 0.2.11 (本地线 · 2026-11-04 — host references survive the rewrite)

**`@file` and `/skill` chips are now invisible to the model, and therefore unbreakable.** A draft is a plain string in the composer store (`dsh-client-ui-conversation/lib/client.js` — `setDraft` writes `d.draft`), and both reference sources serialise to their literal text: the `@` source's codec is `{ clipboardText: (ref) => ref, serialize: (ref) => Promise.resolve(ref) }`, and the `/` skill source inserts `/name ` (`dsh-client-ui-skill/lib/client.js`, `onPick` returns ``{ text: `/${candidate.name} ` }``). So a rewrite could translate `@src/app.ts` into 「那个文件」, add a period inside `@"my plan.md"`, or turn `/code-review` into 「代码审查」 — the chip stops resolving and the operator has to re-pick it by hand, every time.

- **`src/shared/refs.ts` (new): placeholder protection.** `protectRefs` swaps each reference for `⟦n⟧` before the call; `restoreRefs` writes them back verbatim after it. The model never sees the real text, so no instruction can make it damage one. Scanning is boundary-aware rather than regex-greedy: `dev@example.com`, `https://host/a/b`, `and/or`, and `/home/user/a.txt` are left alone; a candidate containing a slash is treated as a path, so `看@src/app.ts哪里慢` protects `@src/app.ts` and leaves 「哪里慢」 in the sentence; trailing punctuation stays in the prose. The quoted form `@"path with spaces"` — the only way the host can express a spaced path — is recognised whole.
- **`REF_SYSTEM_ADDITION` + `withRefRules` (`src/prompts.ts`).** Appended only when the draft carried references, so a reference-free call keeps a byte-identical system prompt. The rules only have to keep the tokens alive — same number, same order, same count, no invented paths, no explaining what a placeholder "really is" — because restoration is mechanical.
- **Nothing is ever dropped.** A placeholder the model swallowed leaves its reference re-appended at the end, and the result carries `refs: { total, restored, missing }` — a new optional field on `EnhanceResult`, absent when the draft had no references. A duplicated or renumbered placeholder is swept: a resolvable number is restored (or handed to an identical twin reference), an unresolvable one is deleted rather than shown to the operator.
- Observability adds two counts to the existing stderr line — `refs=N`, `refsmiss=N` — and still no text: a reference is a path, and paths stay out of the log.
- **The draft is no longer refused for carrying chips.** The composer button used to reject any draft whose input state held `occurrences` (or whose phase was not `plain`) with 「输入内容包含命令或文件引用，暂不支持增强；请先移除后再试。」 — so a draft with one `@file` never reached the route and none of the protection above could run. That guard is gone; the button now refuses only while the host owns the document (`submitting` / `adjudicating`). What is left is stated instead of blocked: `setDraft` clears the composer and re-inserts plain text, so applying a result flattens a chip into its literal text — same path, same command, but no chip highlight, no click-to-open, and a leading `/name` is no longer a claim. The result panel says so (`PanelState.plainRefs` → `panel.plainRefs`) before the apply, not after the operator notices.

Ordering with the existing mechanisms is unchanged: `splitSlashPrefix` still owns the leading command line, references inside the body are protected after it, and the anchor/fidelity gate runs on the placeholder body — a reference is never treated as a literal fact to verify.

- **The trigger glyph is line art now (`src/client/icons.tsx`, new).** The button used to render `✨`, an emoji whose weight and colour come from the platform's emoji font — a heavy filled orange star on Windows — so it sat much denser than the stroke icons the composer ships beside it (microphone, send). `EnhanceStarIcon` and `EnhanceBusyIcon` draw the same idea as 24-unit line art at the host's weight (1.6 stroke, round caps, no fill) and inherit `currentColor`, so the button's own `opacity: 0.75` and hover brightening still apply, and the glyph can no longer change shape per platform. The busy arc keeps its `dsh-pe-spin` rotation; the panel header reuses the star at 13px.
- **Panel chrome takes the host's design tokens.** The card used to carry its own dark/light palette switched by `prefers-color-scheme`, which is a guess: the shell can run dark on a light OS. Every surface now declares `var(--host-token, old-value)` — `--dsw-alias-bg-layer-1` (surface), `--dsw-alias-label-primary` / `--dsw-alias-label-tertiary` (text), `--dsw-alias-border-l2`, `--sys-color-divider`, `--sys-color-state-hover-on-subtle` (borders and hover), `--dsw-alias-state-business-primary` (the apply button, `#4176e6`), `--dsw-radius-md` / `--dsw-radius-sm` and `--dsw-font-family` — so the panel inherits the theme in force instead of inferring it. The `prefers-color-scheme: light` block is down to the one value that is semantic rather than thematic: the error text colour (the host's error token is tuned for fills and reads muddy as small body copy).
- **Error and loading use a narrow card.** Both states carry one line, so they render at `min(460px, 100%)` (`.dsh-pe-panel.is-narrow`) instead of the comparison panel's 880px — an empty panel the width of the composer was a small dialog pretending to be a big one.

New cases: `tests/refs.test.ts` (21: both reference kinds, quoted paths, referenced text glued to Chinese, punctuation, the email/URL/absolute-path/`and/or` non-matches, repeated references, the placeholder spellings a model drifts into, dropped and duplicated placeholders, and Markdown `[1]`) and `tests/refs-route.test.ts` (5 over real HTTP: the model never sees the path and the system prompt carries the rules, a swallowed placeholder is re-appended, both kinds in one draft, the leading command stays out of the body, and a reference-free draft keeps its old response shape) plus three in `tests/client-components.test.tsx` (a chip-bearing draft now issues the request and carries the caveat, a `claimed` first line does too, and a `submitting` draft is still refused).

Tests: 510 across 36 files.

## 0.2.10 (本地线 · 2026-11-04 — the rewrite call stops handing back refusals)

**A provider's declination is no longer shown as the enhanced prompt.** The enhancement call asks a model to restructure a draft; a model that reads the draft's *subject* rather than its *task* answers the request instead — "这个我没法帮你改写…如果你实际想要的是…" — and the panel rendered that apology as the result. Two changes, one layer apart:

- **`rewriterArmor` (default on): a stance block above the strategy.** `REWRITE_STANCE` (`src/prompts.ts`) states the tool position — rewriter, not reviewer, not author — and names the specific failure modes as output errors: no declination, no policy prose, no "here is a safer version", no discussing the draft's subject matter. It is prepended (`withRewriteStance`) so it governs *whether* the rewrite happens while the strategy keeps governing *how*; the strategy's hard rules (never fabricate, body only, mirror the language) are untouched. Chinese first because that is where these refusals arrive from, with an English mirror for models that reason in English. Operator overrides (`systemPrompt`) still receive it — the block is about performing the task at all, not about style — and `rewriterArmor: false` restores the byte-identical pre-`0.2.10` request.
- **One retry, then an honest error.** `isRefusalReply` (`src/shared/refusal.ts`, new) recognises a refusal deterministically: a decline phrase in the head of the reply plus the absence of prompt scaffolding (headings, bullets, numbered steps, labelled fields, a role assignment). On a hit the call is repeated once with `REWRITE_STANCE_ESCALATION` appended, which names the previous turn as the error and forbids explaining the correction. A second refusal is terminal as `upstream` / `reason=refused`, with its own copy in both dictionaries, rather than a "result" that is really a refusal — the fix is routing the call to a model that does not content-review.

Both passes are bounded by construction — never a loop — and the retry drops its deltas for the same reason the fidelity repair does: the panel already streamed the first body. The refusal gate runs before the anchor gate, so a refusal never enters literal-fact verification. `rewriterArmor` is mirrored in `SETTINGS_FIELDS` and both locale dictionaries.

New cases: `tests/refusal.test.ts` (8: the screenshot's declination, English declinations, scaffolding that suppresses the verdict, the scan window, empty replies, an apology that is followed by real work) plus a `refusal gate` block in `tests/enhancer.test.ts` (5: retry succeeds, both passes decline, gate off keeps the old passthrough, a rewrite never spends the retry, an empty reply keeps the empty-response path) and `withRewriteStance` coverage in `tests/prompts.test.ts`.

Tests: 482 across 34 files.

## 0.2.9 (本地线 · 2026-11-04 — prompt armor)

**Prompt armor: an operator-written identity block above every assembled section.** `armorEnabled` (default **off**) prepends a block to the system prompt of every turn. It is the prompt-level half of what `dsh-purge` calls 破甲, ported alone: `src/armor.ts` registers a `prompt-enhance-armor` section at `order = armorOrder` (default `-100000`) with `interpolate: false`, and does not touch `app.asar`, approvals, sandbox modes, or the tool list. What changes is what the model is told about itself; what the runtime permits is unchanged.

The body is read from `armorFile` (default `~/.dsh/prompt-inject.md`, the same file `dsh-purge` uses) whenever that file exists and is non-empty, and from `armorText` otherwise; `~` and `${DSH_HOME}` expand, and the file is cached by mtime so an edit lands on the next turn. `resolveArmorText` returns its provenance (`file` / `inline` / `none` plus a `note` such as `ENOENT` or `empty`) instead of silently doing nothing, so a mistyped path is diagnosable rather than invisible.

Three decisions worth recording:

- **Unknown `{{variable}}` tokens are escaped, not passed through.** Only `{{model}}` and `{{provider}}` are registered by the harness; everything else becomes `{ {name} }`. An unregistered `{{cwd}}` is a hard prompt-assembly failure on this runtime — the failure that produced `dsh-purge` 1.4.1 — and one stray token in an operator file must not cost a turn.
- **Two registration paths that dedupe.** `ctx.systemPrompt.section()` is the documented seat; the `system-prompt/assemble` event is the fallback for hosts where it is absent or was not yet mounted. Both check the section name first, so installing both cannot inject twice, and the event handler always returns a usable assembly: a downstream throw falls back to the upstream assembly instead of failing the turn.
- **No double injection across plugins.** A body another plugin already injected verbatim (whitespace-insensitive comparison) is left alone, so running this alongside `dsh-purge` pointed at the same file costs nothing extra.

The armor is host-side only: no browser code reads it, so it is not mirrored in `ClientSettings`, but it is editable from the plugin's own settings page (`armorEnabled`, `armorFile`, `armorText`, `armorOrder` in `SETTINGS_FIELDS` plus both locale dictionaries; `tests/settings-page.test.ts` still locks the field list to the schema).

`mountArmor` is idempotent per registrant context (a `Symbol.for` flag), warns at most once per failure kind, and is exercised by `tests/armor.test.ts` (28 cases: variable escaping, path expansion, file/inline precedence, the mtime cache, dedupe by name and by body, the waterfall contract with and without `next`, a downstream throw, and a host with no seat at all).

## 0.2.8 (unreleased — workspace grounding)

**Workspace-aware enhancement, and the first build of this line to be published.** Until now `0.2.8` existed only as a local build while npm served `0.2.7` as `latest`; this is the version that ships the feature, together with the corrections and behaviour changes recorded below.

**Workspace-aware enhancement.** The rewrite is now grounded on the session's working directory as well as its conversation: `src/workspace.ts` (new) walks `session.header.cwd` through the `ctx.fs` service (`resolve` / `listDir` / `readText`), lists the directory structure, and reads bounded excerpts of the highest-ranked files. That scan is rendered into a `<workspace_context>` block placed after the `<conversation_context>` block and before `<raw_prompt>`, and `WORKSPACE_SYSTEM_ADDITION` is appended to the strategy **only** when such a block exists — the same "context is evidence, the raw prompt wins, never invent a path" contract the conversation layer already used.

Bounds and safety are all configurable (`workspaceAware`, `workspaceRoot`, `workspaceMaxDepth`, `workspaceTreeMax`, `workspaceMaxFiles`, `workspaceMaxFileChars`, `workspaceMaxChars`). A workspace scan is reused for 10 seconds per `fs` provider + session + root + bounds (a retry after a timeout must not re-read the same tree); a failed or empty scan is never remembered, and `workspaceAware = false` disables the layer and that cache together.

## 0.2.3 (2026-09-30)

Four real defects fixed — two of them long-standing, two surfaced only by running the plugin against a live `dsh web` host. Patch release: no feature, config, or API additions, and no behavior change on a host that already worked.

**Upstream fix hints never appeared (`error.upstream.<reason>`).** The host sends `reason` in kebab-case (`invalid-credential`, `rate-limit`, `context-window`, `tool-call`, `max-tokens`) while the dictionaries key those hints in camelCase (`error.upstream.invalidCredential`, …). Building the key as `` `error.upstream.${reason}` `` therefore matched only the three single-word reasons (`auth`, `quota`, `empty`) and silently fell back to the generic line for the other five — the specific copy was shipped but unreachable. `UPSTREAM_ERROR_KEYS` is now an explicit, literal-typed table (`PromptEnhanceKey`), covered by a key-set test plus a per-reason render test on the real panel.

**The streamed route never ended its response.** `/prompt-enhance/enhance-stream` wrote its `done` frame but never called `res.end()`, so the chunked body lacked its `0\r\n\r\n` terminator and the connection stayed half-open: a browser client survived only because it returns on the `done` frame and cancels its reader, while any whole-body consumer (`response.text()`, curl, a reverse proxy, a logging middleware) waited forever and keep-alive could never reuse the socket. The route now ends the response after the final frame, guarded against a client that vanished mid-stream. Locked by SSE end-to-end tests that read the body to completion.

**The plugin could take the whole web boot down.** The browser half declared `settingsScope` in its exported `inject`. Cordis loads a plugin *only while every service named there is available*, and that service belongs to the optional settings surface (`@deepseek-ai/dsh-client-ui-settings`), which a minimal profile need not bundle — so the entry sat `pending` forever and the shell reported `web boot: 1 entry did not activate` on a blank page. The half now hard-requires nothing: `slots`, `locale`, and `settingsScope` all ride optional `ctx.inject`, and `apply()` itself touches no service. Degradation is graceful — no settings surface keeps the bundled default mirror, no locale service renders dictionary keys.

**A missing host field unmounted the composer button.** `EnhanceButton` read `state.imageIds.length` and `state.occurrences.length` directly. Those fields are part of the input snapshot in the dsh lines the plugin was written against, but a slot host is not obliged to expose them; reading `.length` off a missing field throws *during render*, and React answers that by unmounting the entire slot entry behind its error boundary (`slot entry crashed in 'conversation.input.right'`) — the composer silently lost the button while the console filled with one repeated stack trace. Both counts, plus `draft`/`phase`, are now read defensively; an absent field only disables the corresponding advisory guard, never the feature.

**Also:** new SSE frame writer with real socket backpressure (`src/sse.ts`) so a slow reader cannot make the socket buffer grow without bound; the context window budget uses the same Unicode code-point gauge as the input cap and truncates without splitting surrogate pairs; `resolveConfig` normalizes a blank `provider`/`model` pair to `undefined` instead of a surviving `''` that downstream read as "an override exists"; the cross-session busy state uses `aria-disabled` with a readable reason instead of a silently disabled button; `ResultPanel`'s focus restore no longer hands focus straight back out under StrictMode; `peerDependencies` now includes `react-dom` and `@deepseek-ai/dsh-llm`; `files` includes the `docs/` screenshot the READMEs reference; CI runs the Node floor (`22.19`).

Compatibility fix found by testing the plugin on a real 0.1.2-alpha.3 harness, not by inspection: `@deepseek-ai/dsh-settings` moved its registration API — the alpha line dropped the standalone `installSettingsSection()` / `settingsNamespace()` exports and exposes the same wiring as `ctx.settings.installSection(owner, ns, …)`. Because the host half imported those names statically, the plugin failed at module load with `SyntaxError: … does not provide an export named 'installSettingsSection'`, taking the whole web profile down; 0.1.7 fixed the inject list but still crashed there.

Registration now goes through `ctx.inject(['settings'])` — the service-availability gate both generations use internally — with a runtime probe picking the API the mounted service speaks, and the legacy helpers reached through a dynamic import so an alpha build never evaluates the removed names. Verified on a real alpha.3 profile: the layer mounts, the route answers, the client bundle builds with all four injected packages resolved, and the settings service (`dsh-settings-file`) is present so the alpha branch is the one taken.

Tests: 122 (alpha `installSection` branch, legacy standalone-helper fallback, no-service case, and a load-time guard that fails if a static import of the removed names ever comes back).

## 0.1.7 (2026-09-01)

Compatibility fix for the 0.1.2-alpha harness cohort, reported in the upstream market review (zhu1090093659/dsh-web#1282): `@deepseek-ai/dsh-client-runtime` was removed upstream (it never published an alpha), so its entry in `dsh.client.inject` failed to resolve on alpha hosts and the plugin would not load. ## 0.1.6 (2026-08-31)

Errors are now structured: the host sends `{ code, params?, message? }` where `message` is only an optional diagnostic detail (provider raw text, config errors) — the browser renders its localized primary line from `code`/`params` via the locale dictionaries, so non-Chinese UIs no longer see Chinese host copy. `upstream` errors carry an optional `reason` (auth / quota / rateLimit / empty / contextWindow / toolCall / maxTokens / invalidCredential) that picks a specific fix hint; over-length rejections carry `{ count, max }` and reuse the too-long input message. A host-side `formatEnhanceError()` renders the same errors for the `/enhance` command plane, which has no browser dictionary.

Rate limiting counts successful calls only: a stamp lands after the 200 is written, so a run of failures (timeouts, upstream errors, cancellations) no longer burns the user's per-minute window and locks them out right when the model recovers. The concurrency cap still bounds in-flight calls regardless of outcome. `Retry-After` and the `rate-limit` params stay in sync.

Undo stack: the per-session store now has a global entry cap (default 60) with least-recently-written-session eviction, so many long-lived sessions cannot accumulate undo entries without bound (per-session depth 3 unchanged).

Docs: error-code reference table, troubleshooting section, and the success-only rate-window semantics in the zh README; the browser half's single-panel concurrency (1 in-flight request) vs the host `maxConcurrent` cap is documented rather than changed.

Tests: 118 (failed calls do not consume the rate window, structured error params, host-side error rendering, undo-stack global-cap eviction).

## 0.1.5 (2026-08-31)

Features: a `strategyMode` setting (`replace-default` | `extend-default`, default `replace-default` for backward compatibility) — a non-empty custom `systemPrompt` either swaps the built-in strategy out entirely (`replace-default`, the earlier behavior) or is appended after it (`extend-default`), so the built-in hard rules stay in force. Host call logs no longer record the provider/model route, which can carry internal gateway or project identifiers — request id and sizes only.

Security/resource: `Content-Length` fast reject answers `413` before a single body byte is read (the streamed cap stays as the chunked-body backstop), and the connection closes after the refusal so a declared-but-never-sent body cannot pin the socket open. Re-applying the plugin on one context no longer stacks a second admission gate, which would have silently doubled the effective limits. The rate cap and the concurrency cap now answer distinct codes (`rate-limit` / `concurrency-limit`) — the rate branch sends a precise `Retry-After` computed from the sliding window; the concurrency branch sends none, because a busy slot frees whenever an in-flight call settles.

Consistency: input lengths are counted by one shared `countText()` (Unicode code points) everywhere — validation, error copy, and host logs no longer disagree on emoji or composed characters; copy now says 字符/characters and states it is a character count, not a token count.

Docs: single-process scope of the admission caps, undo-stack lifecycle (page memory, 3 per session), the `strategyMode` combination semantics for `systemPrompt`, request-level timeout ownership (host/Node, not the plugin), and a corrected 0.1.2 note on oversized bodies.
